# 系统架构

## 三层架构

本工具采用 C++ + Python 混合架构，通过 pybind11 桥接：

```
┌─────────────────────────────────────────────┐
│         展示层 (Python + Streamlit)          │
│   Web UI、表单输入、结果可视化、报告导出      │
├─────────────────────────────────────────────┤
│              ↕ pybind11 绑定                 │
├─────────────────────────────────────────────┤
│            业务逻辑层 (Python)               │
│   模型分析器、硬件数据库、校准数据管理        │
├─────────────────────────────────────────────┤
│              ↕ 调用                          │
├─────────────────────────────────────────────┤
│           计算引擎层 (C++)                   │
│   FLOPs计算、显存估算、带宽分析、硬件匹配    │
│   并行策略优化、校准系数拟合                 │
└─────────────────────────────────────────────┘
```

## 计算引擎层 (C++)

### 估算引擎 (`estimation_engine.h/cpp`)

负责核心计算，支持 5 种模型类型：

- **Dense**: 基于 Transformer 参数量公式 P ≈ 12·L·d² 推断架构，计算权重/KV Cache/激活值显存
- **MoE**: 基于单专家参数量推断架构，区分总参数（显存）和激活参数（FLOPs）
- **o1 推理**: 在 Dense 基础上乘以推理 token 倍率（2x-10x）
- **多模态**: 语言模型 + 视觉编码器分开估算
- **推荐**: Embedding Table + MLP/Transformer 估算

关键特性：
- GQA/MQA 感知的 KV Cache 计算（num_kv_heads × head_dim）
- SwiGLU FFN 架构支持
- 框架开销建模（运行时 + 内存碎片化）
- 规模相关的开销公式

### 硬件匹配器 (`hardware_matcher.h/cpp`)

根据估算结果推荐最优硬件配置：

1. 计算所需卡数（显存约束 + 算力约束）
2. 选择并行策略（TP/PP/EP）
3. 估算通信开销（区分 NVLink/HCCS/PCIe）
4. 计算预估吞吐量和延迟
5. 按性价比排序

### 校准模块 (`calibration.h/cpp`)

用实测数据修正理论公式的系统性误差：

- 校准系数 = 实际值 / 预测值
- 按 (模型类型, 硬件类型) 分组
- 支持批量导入和持久化

### 共享架构推断 (`architecture_utils.h`)

从参数量推断模型架构（层数、hidden_dim、num_heads）：
- Dense: P ≈ 12·L·d²，d/L ≈ 128
- MoE: 基于单专家参数量推断

## 业务逻辑层 (Python)

### 模型分析器 (`model_analyzer.py`)

- 加载模型预设 (JSON)
- 创建 ModelParams 对象
- 支持自定义参数和预设选择

### 硬件数据库 (`hardware_db.py`)

- 管理硬件规格 (JSON)
- 支持增删改查
- 转换为 C++ HardwareSpec 对象

### 校准管理器 (`calibration_mgr.py`)

- 自动加载默认校准数据
- 支持 CSV 导入导出
- 计算和应用校准因子

## 展示层 (Streamlit)

### 页面

| 页面 | 功能 |
|------|------|
| 算力估算 | 输入模型参数，获取硬件推荐 |
| 多硬件对比 | 同时对比所有硬件性能 |
| 敏感性分析 | 参数变化对性能的影响曲线 |
| 批量估算 | CSV 批量导入导出 |
| 管理 | 硬件和校准数据管理 |

### 图表组件 (`charts.py`)

- 吞吐量对比柱状图
- 显存分布饼图
- 敏感性分析曲线图

## 数据流

```
用户输入 → ModelAnalyzer.create_params()
         → EstimationEngine.estimate()
         → HardwareMatcher.match()
         → CalibrationManager.adjust()
         → 结果展示 + 图表
```
